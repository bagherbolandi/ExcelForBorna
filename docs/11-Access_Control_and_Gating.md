# 11 — کنترل دسترسی نقش‌محور و گیتینگ (تقدم و تأخر ورود اطلاعات)
**نسخه 2.0 — تاریخ: 2026-09-23**

این سند دو مکانیزم امنیتی/فرآیندی سامانه را توضیح می‌دهد که مستقیماً با
`openpyxl` در `src/renderer_v2.py` روی فایل نهایی اعمال می‌شوند:

1. **کنترل دسترسی نقش‌محور** — هر کاربر فقط بخش خودش را ویرایش می‌کند.
2. **گیتینگ (Gating)** — تا اطلاعات مؤثر مرحله قبل ثبت نشده باشد، مرحله بعد
   مجاز به محاسبه/ورود اطلاعات نیست.

---

## 1. مدل دسترسی: «همه می‌بینند، هرکس فقط بخش خودش را ویرایش می‌کند»

### 1.1 مکانیزم فنی (بدون ماکرو، صرفاً قابلیت‌های بومی Excel)

| لایه | مکانیزم | نتیجه |
|---|---|---|
| قفل شیت | `Sheet Protection` روی **همه ۵۳ شیت** با گذرواژه راهبر (`راهبر1404`) | هیچ‌کس نمی‌تواند فرمول‌ها، ساختار یا قالب را تغییر دهد |
| محدوده مجاز ویرایش | `Protected Ranges` (قابلیت «Allow Users to Edit Ranges») با **گذرواژه مستقل برای هر نقش** | فقط دارنده گذرواژه نقش می‌تواند سلول‌های ورودی همان بخش را ویرایش کند |
| مشاهده | انتخاب سلول‌های قفل‌شده برای همه آزاد است (`selectLockedCells=0`) | مدیر پروژه و همه نقش‌ها **همه بخش‌ها را می‌بینند** ولی فقط محدوده خود را ویرایش می‌کنند |

> نکته معماری: چون سلول‌های فرمولی/محاسباتی همگی Locked باقی می‌مانند،
> هیچ کاربری — حتی با گذرواژه نقش — نمی‌تواند فرمول‌ها یا ستون‌های محاسباتی
> را دستکاری کند. ورودی صرفاً در سلول‌های طراحی‌شده ممکن است.

### 1.2 جدول نقش‌ها و گذرواژه‌ها (بازتاب شیت `Access_Control`)

| نقش | گذرواژه ویرایش | محدوده‌های تحت مالکیت |
|---|---|---|
| فروش (`ROL-02`) | `فروش1404` | `Orders` (ثبت/بررسی سفارش)، `Sales_Quotation` (قیمت نهایی و حاشیه)، `Payment_Terms` (نحوه پرداخت)، `Quotation_Versions`، `Customers` |
| مدیر پروژه (`ROL-03`) | `مدیر1404` | `Projects`، `Feasibility`، `Schedule` (مبنای گانت)، `PMO_Summary` — **مشاهده همه بخش‌ها آزاد، ویرایش فقط همین‌ها** |
| مهندسی (`ROL-04`) | `مهندسی1404` | `Engineering`، `BOM_Header`، `BOM_Detail`، `Time_Study`، لیست‌های مرجع `Materials`/`Equipment`/`Products`/`Product_Revisions` و بخش مهندسی `Project_Equipment` |
| بازرگانی (`ROL-06`) | `بازرگانی1404` | `Supplier_Quotes`، `Supplier_Quote_Lines`، `Procurement`، `Purchase_Prices` و بخش قیمت‌دهی `Project_Equipment` + `Suppliers` |
| برنامه‌ریزی تولید (`ROL-05`) | `برنامه1404` | `Planning` (تاریخ نیاز/وضعیت تأمین)، `Inventory` |
| انبار (`ROL-10`) | `انبار1404` | `Receipts` (رسیدها)، `Inventory` |
| مالی (`ROL-07`) | `مالی1404` | `Cost_Lines`، `Costing`، `Budget` |
| مدیریت ارشد (`ROL-08`) | `ارشد1404` | فقط `Management_Approval` (تصمیم: تأیید / رد / برگشت برای اصلاح) |
| راهبر (`ROL-09`) | `راهبر1404` | باز/بستن محافظت شیت‌ها؛ گذرواژه محافظت سراسری شیت‌ها |

### 1.3 نکته مهم درباره گذرواژه‌ها
- گذرواژه‌ها به‌صورت **هش 16-بیتی استاندارد Excel** داخل فایل ذخیره می‌شوند
  (نه متن باز)؛ فقط در شیت `Access_Control` به‌عنوان جدول مرجع سازمانی نمایش
  داده شده‌اند تا توزیع آن‌ها بین واحدها ممکن باشد. برای محیط عملیاتی،
  مقادیر ستون `Edit_Password` در شیت `Access_Control` را پاک کنید.
- تغییر گذرواژه‌ها = ویرایش `seed.ACCESS_ROLES` در `src/seed.py` و اجرای مجدد
  `python src/build_all.py` (فایل به‌صورت قطعی بازتولید می‌شود).

## 2. گیتینگ: تقدم و تأخر ورود اطلاعات

### 2.1 تعریف گیت‌ها (شیت `Gate_Status`)
برای هر پروژه ۸ پرچم مرحله (`S1..S8`) و یک پرچم تصمیم مدیریت ارشد به‌صورت
**فرمول زنده** محاسبه می‌شود؛ سپس گیت‌های تجمعی (`G_PM..G_Senior`) حاصل‌ضرب
پرچم‌های قبلی هستند:

| پرچم | مرحله | شرط تکمیل (فرمول) |
|---|---|---|
| `S1` | فروش | `Ready_Flag=READY` برای سفارشِ پروژه |
| `S2` | مدیر پروژه | ردیف امکان‌سنجی با همه امتیازها + نتیجه + توصیه (`Completed_Flag=COMPLETE`) |
| `S3` | مهندسی | رکورد مهندسی تأییدشده + حداقل یک عملیات زمان‌سنجی + نسخه تأییدشده BOM برای محصول پروژه |
| `S4` | بازرگانی | همه ردیف‌های تجهیزات پروژه `PRICED` + حداقل یک قیمت خرید معتبر (غیرمنقضی) تأییدشده |
| `S5` | برنامه‌ریزی/انبار | همه ردیف‌های نیاز پروژه در `Planning` تأیید شده |
| `S6` | مالی | `Costing` تأییدشده برای پروژه |
| `S7` | فروش | پیشنهاد قیمت `Submitted` |
| `S8` | مدیریت پروژه | گزارش جمع‌بندی در `PMO_Summary` اعلام‌شده (`Report_Date`) |
| تصمیم | مدیریت ارشد | ثبت تصمیم در `Management_Approval` |

ستون `Current_Stage` به‌صورت خودکار «مرحله جاری/مسدودکننده» هر پروژه را
نمایش می‌دهد و ستون `Completion_Percent` درصد پیشروی در چرخه است.

### 2.2 اعمال قفل روی ورود اطلاعات (نه فقط نمایش)
`renderer_v2.GATE_DV` برای ستون‌های ورودی هر شیت یک **Data Validation سفارشی**
ایجاد می‌کند که به ستون گیت متناظر در `Gate_Status` ارجاع می‌دهد. مثال واقعی
اعمال‌شده روی ستون‌های قیمت `Project_Equipment`:

```text
=OR($B3="",IFERROR(INDEX(Gate_Status!$P$3:$P$20,MATCH($B3,Gate_Status!$B$3:$B$20,0)),0)=1)
```

یعنی: تا `G_Com` آن پروژه برابر ۱ نشود، اکسل هنگام تایپ قیمت پیام خطای
«قفل گیت گردش کار» می‌دهد و ورود را **رد می‌کند**. برای شیت‌های غیرپروژه‌محور
(مثل `Purchase_Prices`) از سلول‌های تجمعی ردیف ۱ استفاده می‌شود:
`Any_G_Eng = MAX(G_Eng)`، `Any_G_Com = MAX(G_Com)`، `Any_G_Pln = MAX(G_Pln)`.

### 2.3 ماتریس گیت‌ها (نقشه وابستگی مراحل مطابق درخواست کسب‌وکار)

| # | مرحله | مالک | گیت ورود | قفل می‌شود مگر اینکه… |
|---|---|---|---|---|
| ۱ | دریافت و بررسی سفارش | فروش | — | اطلاعات سفارش کامل شود (CO-01..CO-04 → READY) |
| ۲ | تعریف پروژه + گانت + امکان‌سنجی | مدیر پروژه | گیت ۱ | امتیازهای پنج‌گانه + نتیجه امکان‌سنجی ثبت شود |
| ۳ | اقلام (BOM) + تجهیزات + زمان‌سنجی/نفرساعت | مهندسی | گیت ۲ | مهندسی تأیید + زمان‌سنجی + نسخه تأییدشده BOM |
| ۴ | قیمت‌دهی اقلام/تجهیزات (+نرخ ارز وارداتی) | بازرگانی | گیت ۳ | همه ردیف‌ها قیمت‌گذاری + قیمت خرید معتبر |
| ۵ | مقدار نیاز تولید + زمان‌بندی نیاز + رسید انبار | برنامه‌ریزی و انبارها | گیت ۴ | وضعیت تأمین همه ردیف‌های نیاز ثبت شود |
| ۶ | قیمت تمام‌شده + بودجه راه‌اندازی | مالی | گیت ۵ | تأیید Costing |
| ۷ | قیمت نهایی فروش + نحوه پرداخت | فروش | گیت ۶ | پیشنهاد Submitted |
| ۸ | جمع‌بندی + به‌روزرسانی گانت/امکان‌سنجی + اعلام به ارشد | مدیریت پروژه | گیت ۷ | ثبت تاریخ اعلام گزارش |
| ۹ | تأیید / رد / برگشت برای اصلاح | مدیریت ارشد | گیت ۸ | — |

### 2.4 رفتار «برگشت برای اصلاح»
تصمیم `RETURN FOR REVISION` ثبت می‌شود اما داده‌های مراحل قبل حذف نمی‌شود؛
واحد مربوط مقادیر موجود را اصلاح می‌کند (ویرایش مقادیر ثبت‌شده مجاز است چون
گیت‌ها بر «تکمیل» دلالت دارند نه بر «اولین ثبت») و چرخه از همان مرحله دوباره
طی می‌شود؛ تاریخچه در `Workflow_History` و `Change_Log` باقی می‌ماند.

## 3. راستی‌آزمایی (تست‌های زنده)
تست‌های `T16..T20` در `src/tests.py` دقیقاً همین رفتارها را با تغییر مدل و
ارزیابی مجدد فرمول‌ها اثبات می‌کنند (۲۰/۲۰ پاس — گزارش در `docs/08`):

- **T16** حذف امتیاز امکان‌سنجی → قفل فوری گیت مهندسی و همه گیت‌های بعدی
- **T17** پروژه بدون امکان‌سنجی کامل → گیت بازرگانی بسته، تجهیزات `PENDING`
- **T18** تغییر زمان استاندارد در زمان‌سنجی → تغییر خودکار دستمزد در قیمت تمام‌شده
- **T19** تغییر نرخ ارز در `Settings` → ارزیابی مجدد قیمت ریالی اقلام/تجهیزات وارداتی
- **T20** حذف تاریخ اعلام گزارش → قفل گیت تصمیم مدیریت ارشد
