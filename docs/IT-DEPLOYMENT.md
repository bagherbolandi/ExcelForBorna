# استقرار در شبکه داخلی — بسته واحد IT (شرکت برنا کامپوزیت ایرانیان)

این سند مسیر استقرار فایل روی پوشه مشترک شبکه را مشخص می‌کند. چون اکسل «رمزنگاری سطحی» ندارد،
مدل امنیتی سه‌لایه است:

```
┌──────────────────────────────────────────────────────────────┐
│ ۳. NTFS / Share ACL  ← لایه واقعی (ویندوز، نه اکسل)          │
│ ۲. VBA Role Gate     ← تجربه کاربری: ورود و مخفی‌سازی برگه  │
│ ۱. Sheet Protection  ← بازدارنده: فرمول‌ها از خراب‌کاری امن  │
└──────────────────────────────────────────────────────────────┘
```

## ۱) ساختار پوشه‌ها (پیشنهاد پایه)

```
\\<SERVER>\BornaProjects\
├── _TEMPLATE\                         فقط خواندنی — الگوی مادر
│   └── Project_Management_Borna.xlsm
├── BC-P-1405-01_FRP-Tank\             به ازای هر پروژه یک پوشه
│   ├── 01_PM\      (شناسنامه/گانت/داشبورد — مدیر پروژه)
│   ├── 02_ENG\     (مدارک، BOM، نفرساعت — مهندسی)
│   ├── 03_TRD\     (قیمت‌گذاری/پیش‌فاکتورها — بازرگانی)
│   ├── 04_PLAN\    (نیازسنجی/رسید انبار — برنامه‌ریزی)
│   ├── 05_FIN\     (بها/بودجه/اسناد — مالی)
│   ├── 06_SALES\   (قیمت/قرارداد — فروش)
│   ├── 07_EXEC\    (گزارش‌های تصویب — مدیریت ارشد، خواندنی)
│   ├── 08_RISK\    (ریسک و تغییرات — مشترک)
│   └── Project.xlsm                   فایل اصلی پروژه (خارج از ACL واحدها؛ فقط تیم پروژه)
└── _LOGS\                            گزارش‌های تغییر فایل
```

> اگر بخواهید «هر واحد فقط شیت خودش را ببیند» واقعاً سخت‌افزاری شود، حالت
> چندفایلی (`01_PM\plan.xlsx` + لینک با Power Query/Co-Authoring) را در انتهای همین سند ببینید.

## ۲) گروه‌های امنیتی و سطح دسترسی (ماتریس)

گروه‌های پیشنهادی Active Directory:

| گروه AD | اعضا | روی `Project.xlsm` | روی زیرپوشه خود |
|---|---|---|---|
| `Borna-PMO` | مدیران پروژه + ارشد پروژه | **Modify** | Modify |
| `Borna-Intake` | بازاریابی/ثبت سفارش | Read + Edit ورودی‌های `شناسنامه`* | Modify |
| `Borna-Eng` | مهندسی | Read Only | Modify (فقط `02_ENG`) |
| `Borna-TradeIn` | بازرگانی داخلی | Read Only | Modify (فقط `03_TRD`) |
| `Borna-TradeEx` | بازرگانی خارجی | Read Only | Modify (فقط `03_TRD`) |
| `Borna-Plan` | برنامه‌ریزی/انبار | Read Only | Modify (فقط `04_PLAN`) |
| `Borna-Fin` | مالی | Read Only | Modify (فقط `05_FIN`) |
| `Borna-Sales` | فروش | Read Only | Modify (فقط `06_SALES`) |
| `Borna-Exec` | مدیرعامل + هیئت‌مدیره | Read Only | Read (`07_EXEC`) |
| `Borna-IT` | واحد IT | Full Control (مدیریت) | Modify |

⚠ **معماری تک‌فایلی:** هر واحدِ نویسنده باید روی فایل Modify داشته باشد (وگرنه اکسل اجازهٔ
ذخیره نمی‌دهد)؛ «دیدن فقط شیت خودی» را ماژول VBA در سطح UI اعمال می‌کند و Sheet Protection
(رمز نزد IT) فرمول‌ها را از دست‌کاری حفظ می‌کند. اگر داده‌های واحدها نباید اصلاً قابل‌خواندن
باشد، بخش ۴ (چندفایلی + NTFS) الزامی است.

روی فایل واحد، کل شیت‌ها با Sheet Protection قفل‌اند و فقط سلول‌های زردِ هر واحد unlocked؛
یعنی حتی گروهی که فایل را Modify دارد، در شیت دیگران نمی‌تواند بنویسد.

نکات:
- **قفل ساختار و شیت:** رمزها را در Key Manager/رمزعبور‌ساز سازمان نگه دارید و در `modBorna.bas` و
  بازسازی فایل (`--pwd-user/--pwd-structure`) ست کنید.
- **Trusted Locations** برای اجرا ماکرو روی Share (GPO) — وگرنه هر کاربر باید دستی اجازه دهد.
- **Locking:** اکسل روی Share از قفل فایل استفاده می‌کند؛ هم‌زمان‌نویسی بیش از یک نفر در هر بخش
  مجاز نیست (یا از Excel co-authoring با OneDrive/SharePoint استفاده کنید).
- **بکاپ:** VSS روی سرور + کپی روزانه `_LOGS`؛ هر تغییر گیت را در «تغییرات» ثبت کنید.
- **ممیزی:** روی `\\...\BornaProjects` Auditing (Object Access → Modify) فعال کنید تا حذف/ویرایش فایل‌ها لاگ شود.

## ۳) اجرای ACL (اسکریپت کمکی)

`tools/deploy_acl.ps1` را روی سرور با حقوق Administrator و پس از پر کردن متغیرهای بالا اجرا کنید.
اسکریپت `icacls` را برای هر پوشه پروژه به‌صورت idempotent اعمال می‌کند (`/inheritance:r` +
grant‌های دقیق) و برای `08_RISK` دوگانه‌نویسی PM/IT را می‌سازد.

## ۴) حالت «چندفایلی» (امنیت سخت‌تر — اختیاری)

اگر رمز اکسل برای شما کافی نیست (دیتابیس‌اکسپلور با باز کردن xlsx قابل استخراج است):

1. فایل مادر را حذف کنید و برای هر واحد **یک فایل مجزا با همان ساختار فرمول‌ها** بسازید.
2. داده مشترک (BOM، تاریخ‌ها) در یک فایل مرکزی `MasterData.xlsx` (فقط PMO Modify) قرار گیرد و
   واحدها با Power Query (`From Workbook` با مسیر شبکه) بخوانند — Refresh خودکار صبح هر روز.
3. داشبورد مدیران از MasterData ساخته می‌شود؛ واحدها هیچ‌وقت فایل همکار را نمی‌بینند چون NTFS اجازه نمی‌دهد.

این حالت با اسکریپت قابل بازتولید است: `build_workbook.py --split` در نسخه‌های بعدی؛
برای امروز، همان ماتریس NTFS بخش ۲ + فایل واحدی، حد تعادل است.
