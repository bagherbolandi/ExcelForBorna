# ExcelForBorna — سامانه مدیریت پروژه برنا کامپوزیت ایرانیان

مخزنِ **سازنده و بستهٔ استقرار** فایل اکسل مدیریت پروژه (امکان‌سنجی، گانت، داشبورد مدیریتی، BOM،
قیمت‌گذاری بازرگانی، نیازسنجی تولید، بهای تمام‌شده، فروش و گیت تصویب) با **تقویم شمسی، فونت Tahoma،
زبان فارسی و کنترل دسترسی نقش‌محور (صفحهٔ ورود)**. طراحی بر پایهٔ مراجع PMI PMBOK 7،
Practice Standard for Scheduling، GAO-16-32G، HM Treasury Five-Case و ISO 21502/31000.

> خروجی نهایی یک فایل آفیس است، نه کد اجراشونده؛ این مخزن منبع تولید (Code-as-Workbook) و
> مستندات استقرار شبکه داخلی شرکت است. بازگردانی گفتگوی اولیه:
> [chatgpt.com/s/cx_6ab374fb1d9c81919143149fc1236dfc](https://chatgpt.com/s/cx_6ab374fb1d9c81919143149fc1236dfc)

## گردش کار پوشش‌داده‌شده

`ثبت سفارش/ایده → امکان‌سنجی → گانت → مهندسی (مدارک/TestPlan/BOM/نفرساعت) → بازرگانی (قیمت BOM، ارز و گمرک) →
برنامه‌ریزی و انبار (نیاز خالص و موعد تأمین) → مالی (بها/بودجه) → فروش (قیمت و پرداخت) → جمع‌بندی مدیر پروژه →
تصمیم مدیریت ارشد (تصویب/اصلاح/رد)` — با بازنگری مداوم گانت و امکان‌سنجی توسط مدیر پروژه.

## تولید / بازسازی

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python build/build_workbook.py --out out/Project_Management_Borna.xlsx   # ساخت مادر
python build/check_workbook.py out/Project_Management_Borna.xlsx         # بررسی ساختاری
python build/build_workbook.py --year 1406                               # گانت سال دیگر
python build/build_workbook.py --pwd-user "…" --pwd-structure "…"         # رمزهای یکتای سازمانی
python build/split_deploy.py --master out/Project_Management_Borna.xlsx   # فایل واحدها (حالت شبکه‌ای)
```

## ویژگی‌های کلیدی فایل

- **تاریخ شمسی همه‌جا** — برگهٔ «تقویم» (۱۴۰۳–۱۴۰۸) + تبدیل دوطرفه با `INDEX/MATCH`؛
  ورودی فارسی/لاتین و جداکننده `1405/07/01` یا `1405-07-01` پذیرفته می‌شود؛ تعطیلات رسمی قابل‌ویرایش.
- **گانت روزانه** — نوار مبنایی/واقعی/تأخیر با Conditional Formatting، شبکهٔ ۳۶۵ روزهٔ ۱۴۰۵،
  روزهای کاری واقعی ( NETWORKDAYS.INTL − تعطیلات)، وضعیت خودکار هر فعالیت.
- **BOM ↔ بازرگانی ↔ برنامه‌ریزی ↔ مالی ↔ فروش** — قیمت‌گذاری اقلام مهندسی با کد فنی، نیاز خالص
  انبار، بهای تمام‌شده با سربار/ذخیره، قیمت فروش با مالیات/تخفیف/جدول اقساط — همگی فرمولی و لینک‌شده.
- **داشبورد مدیریتی** — ۱۸ کارت KPI (پیشرفت برنامه‌ای/واقعی، CPI/SPI، حاشیه سود، ریسک‌ها…)،
  منحنی S فازی، نمودار پیشرفت واحدها، بودجه↔واقعی، چک‌لیست گردش فرآیند.
- **ورود و سطوح دسترسی — دو مدل**:
  1. *تک‌فایلی*: `Borna_Login` (VBA) ماتریس W/R/− را از «تنظیمات» می‌خواند؛ شیت‌های غیرمجاز مخفی/قفل
     می‌شوند؛ **مدیر پروژه همه را می‌بیند و فقط در بخش خودش (گانت/امکان‌سنجی/جمع‌بندی/ریسک/تغییرات)
     می‌نویسد**؛ مدیرعامل فقط «تصویب».
  2. *چندفایلیِ شبکه‌ای (دسترسی واقعی)*: `split_deploy.py` برای هر واحد فایل مستقل می‌سازد — فرمول‌های
     زندهٔ همان واحد + اسنپ‌شات فقط‌خواندنیِ دادهٔ بالادستی؛ سایر داده‌ها فیزیکی در فایل نیست.
     مرز واقعی را NTFS می‌گذارد (هر واحد فقط پوشهٔ خودش را Modify می‌کند)؛ چرخهٔ همگام‌سازی مادر:
     `Borna_Collect → Borna_Publish`. جدول کاربران/توکن‌ها در فایل واحدها چاپ نمی‌شود.
- **فونت Tahoma، چیدمان راست‌به‌چپ، بدون متن مورب** در کل فایل.

## وضعیت تست (در همین مخزن)

مجموعهٔ فرمول‌ها با موتور محاسباتی `formulas` روی خروجی واقعی ارزیابی شد: تبدیل تاریخ، ستون‌های سریال/
وضعیت گانت، جمع‌های وزن‌دار، لینک BOM→بازرگانی، نیاز خالص برنامه‌ریزی، بهای تمام‌شده، قیمت‌گذاری فروش و
فیدبک وضعیت پرونده — `build/check_workbook.py` نیز ساختار/ارجاعات/قفل‌ها را پاس می‌کند.

## محدودیت‌ها

- ماکرو نیازمند Trusted Location روی Share است؛ بدون ماکرو، فایل کاملاً کار می‌کند ولی «دید نقش‌محور» ندارد.
- قفل‌های اکسل رمزنگاری داده نیستند؛ برای محرمانگی واقعی بین واحدها، حالت چندفایلی سند IT را اجرا کنید.
- منحنی S و شاخص‌های EVM ساده‌سازی‌شده‌اند (مبنای خطی/پله‌ای) و جایگزین نرم‌افزار کامل EVM نیستند.
- بازهٔ ستون‌های گانت و تقویم هنگام build تعیین می‌شود؛ برای تغییر، بازسازی کنید.
